# Manifold RAID — Current ISR Research Hypothesis

## Research premise

Can execution history become a **derived runtime artifact** rather than the primary persistent artifact?

Manifold RAID investigates whether, for identifiable computational classes, persistence can be reduced to an **Invariant State Representation (ISR)** plus the constraints and transform rules needed to generate a valid execution trajectory when required.

The current model therefore separates:

- **what must persist** — invariant state, admissibility rules, transform-family identity, generation policy, and closure/equivalence conditions;
- **what can be generated** — the actual execution trajectory;
- **what may be emitted temporarily** — a runtime trace for verification/audit.

## Current hypothesis

> Identifiable computational classes admit discoverable invariant reconstruction records with a minimum representation fidelity `F_min` sufficient to dynamically generate admissible, behaviorally equivalent executable trajectories without requiring preservation of the original execution history.

This is stronger and more specific than the earlier “reconstruct the prior trace” formulation. The current target is not historical replay. It is **generation of a valid admissible trajectory from invariant constraints**.

## Admissible-transform principle

For a current state `SR_t`, active constraints `C_t`, and transform family or vocabulary `T_G`:

```text
A_t = { T in T_G | (SR_t, T, T(SR_t)) satisfies C_t }
```

Only members of `A_t` may be applied.

A dynamic trajectory is then generated by repeated admissible transforms:

```text
SR_0 --T_0--> SR_1 --T_1--> ... --T_n--> SR_{n+1}
```

subject to:

```text
T_t in A(SR_t, C_t, T_G)
```

for every step and a declared terminal closure/equivalence condition.

## Persistent representation

The persistent record may include:

- invariant or entry state `SR_0` / invariant projection `Gamma(SR)`;
- domain/state/container constraints;
- transform-set identity;
- trajectory-family identity `T_G` where applicable;
- constraint-mask/admissibility rules;
- HDRP register initialization or momentum seed where needed;
- OGSI/family-discrimination metadata where needed;
- branch-preservation/tie-break policy;
- terminal exit condition;
- behavioral-equivalence relation;
- closure fingerprint/hash;
- version/hash identities for the generator and verifier rules.

A full historical trace is not a required component of the current general model.

## Behavioral equivalence

“Behaviorally equivalent” is not narrative similarity and does not require identical hidden internal steps unless the experiment explicitly demands them.

It must be defined by a machine-checkable relation such as:

- identical terminal state;
- identical observable output;
- equivalent bounded outcome;
- successful declared closure condition;
- exact byte identity where that is the test requirement;
- another predeclared verification relation.

The verifier determines acceptance.

## Branching and non-uniqueness

The architecture does not assume every admissible state has a single valid next transform.

When multiple continuations remain:

- preserve the admissible branch set;
- rank using HDRP trajectory delta / momentum coherence;
- use OGSI or other declared family information;
- apply a deterministic tie-break only where explicitly defined;
- defer commitment when later information can resolve the branch.

This avoids manufacturing determinism by incorrectly pruning legitimate admissible continuations.

## Fundamental research questions

1. Can sufficient invariant reconstruction records be discovered algorithmically for identifiable computational classes?
2. What minimum representation fidelity `F_min` is required to generate a behaviorally equivalent trajectory?
3. How small can the persistent representation become when the historical execution path itself is not stored?
4. Under what conditions does the admissible-transform set remain non-empty from entry state to valid closure?
5. When multiple admissible continuations exist, what information is sufficient to preserve or resolve them without retaining historical trace state?
6. Which computational classes admit dynamically generated admissible trajectories, and which fundamentally require richer historical state?
7. What formal guarantees can be established for the generated trajectory and terminal state?
8. What memory, bandwidth, energy, discovery, generation, and verification trade-offs emerge relative to trace/state persistence?
9. Can an admissible trajectory be different from the historical trajectory yet satisfy the same declared behavioral-equivalence relation?
10. What constraints are necessary to prevent local admissibility from leading to a dead end that cannot satisfy terminal closure?

## Demonstrated bounded evidence

The recovered July prototype established, within its test scope:

- raw execution traces were removed before regeneration in the tested workflow;
- 4 / 4 verification/round-trip passes;
- zero measured drift under the declared relation;
- aggregate representation ratio `C_r = 2.49x`;
- successful rejection of an invalid `bad_loop.g8son` path without seed acceptance;
- unchanged protected source artifacts under SHA-256 integrity checks;
- successful test-process exit.

This supports the narrower proposition that **verified compact representation can drive bounded regeneration without retaining the raw trace in the tested cases**.

## Current extension not yet generally proven

The following are current architectural hypotheses/extensions rather than claims established by the four-case prototype:

- that the generator can discover a different admissible trajectory than the historical one while preserving behavioral equivalence;
- that arbitrary transform vocabularies can be reduced to a useful admissible set at each step;
- that every useful computational class admits a compact ISR;
- that dynamic generation always yields a unique path;
- that local admissibility alone guarantees eventual closure;
- that the current representation is minimal;
- universal storage, bandwidth, or energy advantage.

## Falsification

The hypothesis is falsified for a target class if one or more of the following occurs under the declared experiment:

- no sufficient invariant record can be discovered;
- the admissible-transform set becomes empty before valid closure;
- generated execution fails behavioral equivalence;
- branch ambiguity requires preservation of essentially the full historical trace;
- verification cannot bound correctness to the required level;
- dynamic generation cannot terminate under the declared resource bound;
- total discovery/storage/generation/verification overhead removes the intended resource advantage.

## Low-resource significance

If validated for useful classes, Manifold RAID would shift persistent computation from **stored execution history** toward **stored invariant state + admissible transform structure**.

Execution would then be regenerated when needed, allowing memory, bandwidth, and storage cost to depend on the size of the invariant representation rather than directly on the length of the historical execution trace.
